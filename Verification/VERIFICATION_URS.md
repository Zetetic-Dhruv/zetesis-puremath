# Verification URS — Tier 0..3 Integration for `zetesis-puremath`

Inquiry URS (grammar + action-space) for wiring `lean4checker` (Tier 2) and
`comparator + Landlock` (Tier 3) onto the auto-extracted Challenge / Solution
corpus. This URS is the planning artifact for the task; it sits next to
`Extract.lean` so the next session can resume cold.

---

## A — Axioms / identity (non-negotiable)

1. **Zero `sorry` in `ZPM/`.** Tier 0 (`lake build`) fails on any `sorry` inside `ZPM/`.
2. **Permitted axiom closure = `{propext, Quot.sound, Classical.choice}`.** Any Solution theorem whose `#print axioms` names anything else is a Tier 1 failure, not a warning.
3. **Challenge and Solution are auto-generated.** Hand-editing either is forbidden. Drift is checked in both GitHub CI and GitLab CI via `git diff --exit-code` after re-running `scripts/build_verification.sh`.
4. **Comprehensive, not curated.** The challenge set covers every public `ZPM.*` theorem (currently 114), modulo the `isAutoGenerated` filter (equation lemmas, `congr_simp`, `injEq`, `sizeOf_spec`, `noConfusion*`). There is no hand-picked "crown jewels" subset.
5. **Comparator runs under a real Landlock sandbox on GitLab CI.** The Tier 3 PASS artifact must record `sandbox: landrun (Landlock)` — no mocked sandbox.
6. **Toolchain-matched tooling.** `lean4export` and `comparator` are cloned at HEAD in CI but pinned to the repo's `lean-toolchain` before `lake build` runs. Mismatch is a pipeline failure, not a warning.

## R — Representation / grammar

- **Theorem `n`**: a `ZPM.*` declaration with `ConstantInfo.thmInfo` that is not `Name.isInternal` and not matched by `isAutoGenerated`.
- **Challenge entry**: `theorem challenge_<flat(n)> : <delab(type(n))> := sorry` emitted into `Verification/ChallengeCrown.lean`.
- **Solution entry**: `theorem challenge_<flat(n)> : <delab(type(n))> := @n` emitted into `Verification/SolutionCrown.lean`. The `@n` re-export forces Lean to check the Challenge type matches `n`'s type up to definitional equality.
- **flat(n)**: `n.toString.replace "." "_"` — the unqualified identifier used to name the challenge.
- **Crown config**: `Verification/config.crown.json` with `challenge_module`, `solution_module`, `theorem_names = ["challenge_<flat>" ∀n]`, `permitted_axioms`, `enable_nanoda`.
- **Axiom closure of a theorem**: the set reported by `#print axioms challenge_<flat(n)>` after importing `Verification.SolutionCrown`.
- **Drift**: `git diff` after re-running `scripts/build_verification.sh`. Non-empty diff = stale artifact.

## Checks (Pl / Coh / Inv / Comp for this task)

- **Pl** (non-trivial, instantiable, consistent): Regenerating artifacts from a fresh environment must produce byte-identical files to the committed ones. If not, `isAutoGenerated` or delab options are non-deterministic — that's a Pl-kill.
- **Coh** (composable with other `act(·)`): CI freshness diff + local build + comparator all consume the same four artifacts. Any decoupling breaks this.
- **Inv** (survives perturbation): Adding a new theorem to `ZPM/` and running `scripts/build_verification.sh` should grow the challenge set by exactly one entry, update the config, and leave the rest byte-identical (given deterministic sort).
- **Comp** (coverage): Tier 0 ✓, Tier 1 needs PrintAxioms fix, Tier 2 needs one successful workflow_dispatch run, Tier 3 needs GitLab mirror + token + green pipeline. Comp climbs from ~0.5 to 1.0 over this task.
